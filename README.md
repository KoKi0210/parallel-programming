# М1-КР13-J: Асинхронно изпълнение на граф от зависими задачи с CompletableFuture

Проект по паралелно и асинхронно програмиране в Java. Изследва се влиянието на топологията на ориентиран ацикличен граф (DAG), обема на работа и дължината на критичния път върху паралелното ускорение и ефективност.

---

## 1. Системни изисквания

* **Java Development Kit (JDK):** Версия **17** или по-нова.
* **Външни библиотеки:** Не са необходими. Проектът използва единствено стандартната Java библиотека (`java.util.concurrent`, `java.io`, `java.util`).
* **Операционна система:** Linux, macOS или Windows.

---

## 2. Структура на проекта

```text
.
├── src/
│   ├── Main.java                    # Експериментален стенд с warm-up и бенчмаркове (default пакет)
│   ├── Executors/                   # пакет Executors
│   │   ├── AsyncExecutor.java       # Асинхронен двигател с CompletableFuture и ExecutorService
│   │   └── SequentialExecutor.java  # Последователно изпълнение чрез топологично сортиране (Kahn)
│   ├── Graph/                       # пакет Graph
│   │   ├── GraphAnalyzer.java       # Изчисляване на W, T_inf и паралелизъм по етапи
│   │   └── GraphLoader.java         # CSV парсер за зареждане на графа
│   └── Model/                       # пакет Model
│       ├── ExecutionResult.java     # Модел за резултати (време в ms и контролна сума)
│       └── TaskNode.java            # Модел на задачата и детерминирано CPU натоварване
├── graph1_wide.csv                  # Граф 1: Широк (W = 1000, T_inf = 370)
├── graph2_deep.csv                  # Граф 2: Дълбок (W = 1000, T_inf = 830)
└── README.md                        # Настоящият файл с инструкции
```

Директориите в `src/` съответстват на Java пакетите (`package Executors;`, `package Graph;`, `package Model;`). `Main` е в безименния пакет и импортира останалите класове.

## 3. Компилиране и стартиране през терминал (CLI)

Уверете се, че текущата директория в конзолата е **коренът на проекта** (където се намират папката `src` и CSV файловете `graph1_wide.csv` и `graph2_deep.csv`).

### Linux / macOS

1. **Компилиране на изходния код:**
   ```bash
   javac -d bin $(find src -name "*.java")
   ```
   *Забележка:* Тази команда компилира всички `.java` файлове от `src` и поддиректориите ѝ (`Executors`, `Graph`, `Model`) и записва генерираните `.class` файлове в новосъздадена директория `bin`, запазвайки структурата на пакетите.

2. **Стартиране на експериментите:**
   ```bash
   java -cp bin Main
   ```

### Windows (Command Prompt / PowerShell)

1. **Компилиране на изходния код:**
   ```cmd
   javac -d bin src\*.java
   ```

2. **Стартиране на експериментите:**
   ```cmd
   java -cp bin Main
   ```

## 4. Стартиране в среда за разработка (IDE)

### IntelliJ IDEA
1. Отворете папката на проекта (`File -> Open...`).
2. Щракнете с десен бутон върху папката `src` в дървото на проекта и изберете **Mark Directory as -> Sources Root**.
3. Отворете `src/Main.java`.
4. Уверете се, че в конфигурацията за стартиране (**Run/Debug Configurations**) полето **Working directory** сочи към основната директория на проекта (за да може програмата да намери CSV файловете).
5. Стартирайте класа чрез бутона **Run** или клавишна комбинация `Shift + F10`.

### Visual Studio Code
1. Отворете папката на проекта с инсталиран **Extension Pack for Java**.
2. Отворете файла `src/Main.java`.
3. Натиснете бутона **Run Java** над `main` метода или натиснете `F5`.
4. *Забележка:* По подразбиране VS Code използва коренната папка като работна директория, така че CSV файловете ще бъдат открити автоматично.

## 5. Входни файлове (CSV формат)

Графите се подават като обикновени текстови файлове с разделител запетая. Формат на редовете:

```csv
id,weight,dependencies
T1,50,
T2,120,T1
T8,150,T2;T3;T4
```

* `id`: Уникален текстов низ, идентифициращ задачата.
* `weight`: Цяло число, определящо обема изчислителна работа (брой CPU итерации).
* `dependencies`: Списък от преки предшественици, разделени с точка и запетая (`;`). За начални задачи полето се оставя празно.

## 6. Какво прави програмата при стартиране?

1. **Анализ на графа:** Автоматично пресмята и извежда:
   - Общата работа $W$;
   - Критичния път $T_\infty$;
   - Максималното теоретично ускорение $S_{max} = \frac{W}{T_\infty}$;
   - Разпределението на независимите задачи по етапи (нива).
2. **Warm-up фаза:** Изпълнява 5 предварителни цикъла за стабилизиране на JIT компилатора и системните нишки.
3. **Последователно измерване:** Изпълнява топологично сортирания граф последователно (10 итерации за усредняване).
4. **Асинхронно измерване:** Стартира графа с `CompletableFuture` при конфигурации от нишки $P \in \{1, 2, 4, 8\}$.
5. **Валидация:** Сравнява контролната сума (`checksum`) между последователното и паралелното изпълнение за гарантиране на детерминизма и коректността.
